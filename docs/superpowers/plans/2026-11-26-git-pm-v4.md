# git-pm v4 迭代 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（延续既有流程：实现者/审查者均为 fixer 独立会话，模型 miaoyun/glm-5.3-flash）。

**Goal:** 四点需求：1) 项目窗口树状结构（名称左对齐）；2) 文件浏览器列宽可调；3) 界面与菜单中英文切换；4) 同一套代码可在 Linux 编译执行。

**Tech Stack:** 新增 `egui_extras`（TableBuilder 可调列宽，本轮唯一新运行时依赖）；`src/i18n.rs` 翻译模块（零依赖）。

## Global Constraints

- 延续 v1–v3 全部约束：gitpm.db 程序当前目录；git 仅经 CLI；领域模块不依赖 egui；错误 match 不 panic；凭据脱敏不回归。
- 裁定（预检）：
  - 树状项目：项目按**父目录路径层级分组**为可折叠树节点（默认展开），项目名称左对齐；无共同层级时按盘符/根分组。选中行为与现状一致（点击项目行选中）。
  - 列宽可调：浏览器表格迁移到 `egui_extras::TableBuilder`（resizable 列），保留名称/类型/大小/修改时间四列与状态图标。
  - i18n：`src/i18n.rs` 提供 `Lang::{Zh,En}` + `t(lang, key)` 查表；语言菜单「Language / 语言」点击即切（不重启），选择持久化 meta（key=`lang`，b"en"/b"zh"，缺省 zh）；覆盖全部 UI/菜单/对话框/提示文案（git 命令原始输出与领域层错误文案不翻译）。
  - 跨平台：main.rs 字体候选加 Linux 常见 CJK 字体路径；`windows_subsystem` 属性保持（非 Windows 编译器忽略）；browser.rs 非 Windows 的 modified 沿用 UTC 回退（已知局限）；验证 = `rustup target add x86_64-unknown-linux-gnu` + `cargo check --target`（无链接器要求）全绿 + WSL 若可用则真机 `cargo test`。

## Review Focus

1. i18n 覆盖完整性 — grep app.rs 不应再有硬编码中文 UI 字符串（领域层/db 错误文案除外，需白名单裁定）。
2. 树分组逻辑 — 重复父目录合并、根路径归组、选中态在折叠后仍保持。
3. TableBuilder 迁移 — 状态图标/置灰/点击进入行为不回归；列宽持久化非必需。
4. Linux 编译 — cargo check 无 Windows 专属 API 泄漏（winresource/build.rs 门控正确）。
