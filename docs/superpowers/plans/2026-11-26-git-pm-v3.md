# git-pm v3 迭代 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（延续 v1/v2 流程：实现者/审查者均为 fixer 独立会话，模型 miaoyun/glm-5.3-flash）。

**Goal:** v3 七点需求：1) 推送远端能力；2) 生成器密码明文显示；3) 浏览器文件状态图标；4) 提交历史窗口；5) 工具栏图标；6) exe 图标；7) 主密码修改。

**Tech Stack:** 新增 build-dependency `winresource`（仅构建期嵌入 exe 图标，Windows 定向）；egui 内置 emoji-icon 字体常量做工具栏/状态图标（零运行时新依赖）。

## Global Constraints

- 延续 v1/v2 全部约束：gitpm.db 程序当前目录；git 仅经 CLI；领域模块不依赖 egui；错误 match 显示不 panic；凭据明文不落日志/输出区（后台路径必须 redact）。
- 裁定（预检）：
  - 推送远端：对话框列出 `git remote` 结果供选择 + 分支名输入 + `-u` 勾选；无 remote 时提示先添加（v3 不做 remote 添加 UI）。
  - 生成器明码显示：明文只在本机内存，接受；默认明文、可选遮蔽切换。
  - 文件状态图标：用 porcelain 状态映射到浏览器条目——M=修改（黄）、A/??=新增（绿）、D=删除（红）、UU/AA/DD=冲突（红底加粗"!"）；按仓库根相对路径匹配（含目录前缀匹配：目录下有任何变更条目则目录标记）。
  - 提交历史：`git log` 默认 10 条，「加载更多」每次 +20；只读窗口。
  - exe 图标：assets/icon.ico 已生成；`winresource` build.rs 嵌入，非 Windows 忽略。
  - 主密码修改：需验证旧密码 → 新盐派生新密钥 → 重加密 verifier 与全部凭据 → 事务写回；失败任一步则整体不生效（旧数据完好）。

## Review Focus

1. **主密码修改原子性**（Task C/D）— 中途失败不得损坏 vault；新主密码可解锁、旧密码被拒、凭据明文不变。→ 单元测试。
2. **log 解析健壮性**（Task B）— 空仓库、含换行的 subject（用 %x00 类分隔符或逐字段 format）、非 UTF-8 输出 lossy。
3. **状态图标路径匹配**（Task B/E）— porcelain 路径 vs 浏览器相对路径大小写（Windows）、重命名 "R  old -> new" 解析。
4. **push 对话框异步**（Task E）— 沿用 Task 5(v2) busy 通道模式，凭据注入路径 redact 不回归。

### Task B: git.rs 领域扩展（remote_list + log）
**Files:** Modify `src/git.rs`（TDD）
**Interfaces:**
- `pub struct CommitInfo { pub hash: String, pub author: String, pub date: String, pub subject: String }`
- `pub fn remote_list(repo: &Path) -> Result<Vec<String>, String>`（`git remote`，空 → Ok(vec![])）
- `pub fn log_recent(repo: &Path, skip: usize, limit: usize) -> Result<Vec<CommitInfo>, String>`（`git log --skip=N -n=LIMIT --date=format:'%Y-%m-%d %H:%M' --pretty=...`；字段间用单元分隔符 `\x1f` 防换行注入；空仓库/无提交 → Ok(vec![])；输出 lossy）
- [ ] 失败测试（temp 仓库：git init + config user + 2 commits）：remote_list 空仓 → 空；log_recent 顺序/字段解析、skip 翻页、空仓库 Err 或空（裁定：无 HEAD → Ok 空）。
- [ ] Commit `feat: git remote list and commit log domain functions`。

### Task C: 主密码修改（crypto.rs + db.rs）
**Files:** Modify `src/crypto.rs`、`src/db.rs`（TDD）
**Interfaces:**
- db.rs：`pub fn all_credentials(conn) -> Result<Vec<(i64, CredentialRecord)>, ...>`（如已有等价读取则复用）；`pub fn update_credential_ciphertext(conn, id, new_ciphertext, new_nonce)`；meta verifier 更新复用 set_meta。
- 核心流程函数（放 db.rs，名 `change_master_password(conn, old_pw, new_pw) -> Result<(), CryptoError/String>`）：unlock 验证旧密码 → 新盐派生新密钥 → 解密全部凭据用新密钥重加密 → 事务内写 verifier(盐+密文)+全部凭据 → commit；任一步失败整体回滚、返回 Err。
- [ ] 失败测试：建库+存 2 凭据 → change → 新密码 unlock 成功、旧密码 unlock 失败（WrongMaster）、凭据明文逐字不变；错误旧密码 change → Err 且数据原样（仍可用旧密码解锁）。
- [ ] Commit `feat: atomic master password change with credential re-encryption`。
